### ⚙️ tech-stoic approach

i have a simple rule: **why do it if you don't have to?**

if the system can handle something reliably, i'd rather not make a human remember, configure, or coordinate it.

i like software where the wrong thing is hard to do and the obvious thing just works.

---

### 🚀 engineering focus

* **simplicity > hype**: building modular apps (react, next.js, fsd) without trendy bloat or architecture for architecture's sake.
* **dx & tooling**: custom clis, sdks, generators, and shared configs - if people keep doing the same setup by hand, i'd rather encode it once.
* **api design**: typesafe, context-aware apis that make invalid states and invalid operation sequences hard to express.
* **legacy taming**: reverse-engineering undocumented codebases and migrating them to typesafe ts without production downtime.
* **pragmatic infra**: linters, formatters, docker, gitlab ci, and automated guardrails that don't rely on everyone remembering the rules.
* **agentic ai workflows**: using ai for mechanical work without outsourcing architectural judgment to it.
* **performance tuning**: chopping bundle sizes, optimizing real-time streams, and building offline-first apps.

---

### 🛠️ tech stack

* **languages & core**: typescript, javascript
* **frontend ecosystem**: react 19, next.js, solidjs, rtk (redux toolkit), apollo client, zustand
* **architecture & patterns**: feature-sliced design (fsd), backend-driven ui, offline-first architectures
* **ui & styling**: tailwindcss, shadcn, radix-ui, base-ui, custom design systems
* **mobile development**: react native (android/ios offline-first apps)
* **tooling & infra**: custom clis, vite, docker, gitlab ci, oxc stack, automated pre-commit & ci checks
* **testing & monitoring**: vitest, playwright, sentry, apollo / rest / graphql integrations
